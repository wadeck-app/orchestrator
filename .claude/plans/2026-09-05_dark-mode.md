# Plan: Dark Mode (UX-06)

All components already use semantic CSS tokens — no raw Tailwind colors in non-legacy code. Dark mode is a CSS variable override.

## Implementation

1. Add `[data-theme="dark"]` overrides in `packages/orch-app/src/index.css`:

| Token | Light | Dark |
|-------|-------|------|
| `--color-bg` | #f8fafc | #0f1117 |
| `--color-surface` | #ffffff | #1a1d2e |
| `--color-border` | #e2e8f0 | #2d3148 |
| `--color-content` | #1e293b | #e2e8f0 |
| `--color-muted` | #64748b | #8892b0 |
| `--color-muted-bg` | #f1f5f9 | #252840 |
| `--color-primary` | unchanged | adjust if contrast fails |
| `--color-danger` | unchanged | adjust if contrast fails |

2. NavBar: add Moon/Sun toggle (Lucide), persist to localStorage `orch-theme`.

3. `App.tsx`: on mount + toggle, set `document.documentElement.dataset.theme`.

## Validation (mandatory — use agent-browser)
Screenshots required in dark mode for: home grid, home list, job detail, audit log, schedule, job form. Fail criteria: any invisible text, contrast < 4.5:1, raw-color violation introduced.

## Known risk
LogViewer uses hard-coded dark terminal palette (`bg-gray-900`, `text-green-400`) — intentional, must stay dark in both modes. Suppress violations with existing reason.
