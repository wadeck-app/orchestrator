# Frontend -- Orch Web Dashboard

**Version:** v0.1
**Last updated:** 2026-08-31
**Status:** Draft

## Overview

The frontend is split across two packages. `orch-ui` contains reusable domain-specific React components for the orchestrator. `orch-app` is the Vite SPA that assembles those components into pages. Both build on `@wadeck-app/dsl-ui` (base component library) and `@wadeck-app/dsl-renderer` (registry-based rendering engine), published from the `wadeck-app/dsl-view` repo.

## orch-ui Package

Exports domain-specific components. Built with `tsc --build`. Peer deps: react, @wadeck-app/dsl-ui, tailwindcss.

### Exported Components

| Component | Key props | Purpose |
|---|---|---|
| `JobCard` | `job: Job, lastRun: RuntimeEntry \| null, onTrigger, onToggle` | Summary card shown in the job list |
| `JobStatusBadge` | `exitCode: number \| null, running: boolean` | Green/red/grey pill indicating last run outcome |
| `NextFireCountdown` | `job: Job` | Displays "fires in Xm Ys" for cron jobs; "on startup" for startup jobs |
| `JobForm` | `initial?: Partial<Job>, onSubmit, onCancel` | Add/edit form; fields shown conditionally by `type` |
| `LogViewer` | `jobId: string, fetcher: Fetcher` | SSE-powered log tail; auto-scrolls; "paused" mode on scroll-up |
| `TriggerButton` | `jobId: string, onTrigger` | "Run now" button with loading state |
| `EnableToggle` | `job: Job, onToggle` | Switch for enabled/disabled state |
| `RunHistory` | `entries: RuntimeEntry[]` | Table of recent runs with startedAt + exitCode |

### JobForm fields (v1)

Fields rendered unconditionally: `label`, `command`, `cwd`, `enabled`, `triggerMode`.

Fields rendered conditionally:
- `type === 'cron'` -- `schedule` (cron expression input with human-readable preview)
- `type === 'startup'` -- `delaySeconds`
- `type === 'once'` -- no extra fields (fires once at add time)

Fields deferred to v2: `liveness`, `onExitCode`, `missedFiring`.

## orch-app Pages and Routes

Built with Vite 6 + `@vitejs/plugin-react` + Tailwind + PostCSS. React Router v7 for routing.

```
/                     -- Job list
/jobs/:id             -- Job detail + run history
/jobs/:id/logs        -- Live log viewer
/jobs/new             -- Add job form
/jobs/:id/edit        -- Edit job form
```

### Page: / (Job List)

- Renders all jobs as `JobCard` components in a responsive grid
- Search bar (filter by label or command substring)
- Filter chips: All / Cron / Startup / Once / Failed
- Each card shows: `JobStatusBadge`, `NextFireCountdown`, `TriggerButton`, `EnableToggle`
- "Add job" button links to `/jobs/new`

### Page: /jobs/:id (Job Detail)

- Header: job label, type badge, `EnableToggle`, `TriggerButton`
- Config section: readonly display of all v1 fields (label, type, command, cwd, schedule/delay, triggerMode)
- "Edit" button links to `/jobs/:id/edit`
- "View logs" button links to `/jobs/:id/logs`
- `RunHistory` table (last 20 entries from GET /api/jobs/:id)
- "Delete" button with confirmation dialog (uses `ConfirmDialog` from @wadeck-app/dsl-ui)

### Page: /jobs/:id/logs (Log Viewer)

- Full-height `LogViewer` component
- Auto-connects SSE on mount; disconnects on unmount
- "Back to job" link

### Page: /jobs/new and /jobs/:id/edit

- `JobForm` component
- On submit: POST /api/jobs (new) or PUT /api/jobs/:id (edit)
- Validation errors displayed inline; server-side `validateJob` errors surfaced as field-level messages

## DSL Renderer Integration

`@wadeck-app/dsl-renderer` is used for its `createRegistry` utility and the `GenericPageRunner` component where page layouts benefit from DSL-driven composition. For pages with straightforward data-fetching and no dynamic layout needs, direct React components are used instead.

The component registry is defined in `orch-app/src/registry.ts`:
```ts
import { createRegistry } from '@wadeck-app/dsl-renderer'
import { allEntries } from './generated/entries' // auto-generated by entriesGenerator

export const registry = createRegistry(allEntries)
```

`@wadeck-app/dsl-ui` components (ButtonAction, DataTable, Section, PageHeader, etc.) are available to all pages and are re-exported from `orch-ui/src/index.ts` for convenience.

## Idle Heartbeat

`orch-app` implements a heartbeat hook (`useHeartbeat`) that:
1. Uses the Page Visibility API (`document.visibilityState`)
2. Sends `POST /api/heartbeat` every 30 seconds while `visibilityState === 'visible'`
3. Stops sending when the tab is hidden or the component unmounts
4. Starts immediately on mount if the tab is visible

```ts
// packages/orch-app/src/hooks/useHeartbeat.ts
export function useHeartbeat() {
  useEffect(() => {
    if (document.visibilityState !== 'visible') return
    const id = setInterval(() => {
      fetch('/api/heartbeat', { method: 'POST' }).catch(() => {})
    }, 30_000)
    const onVisibility = () => {
      if (document.visibilityState === 'hidden') clearInterval(id)
    }
    document.addEventListener('visibilitychange', onVisibility)
    return () => {
      clearInterval(id)
      document.removeEventListener('visibilitychange', onVisibility)
    }
  }, [])
}
```

`useHeartbeat` is called once at the app root (`App.tsx`).
